    What the program did

    The same steps the C++ program prints in the terminal, run on the text you just checked.

    1. Split into wordsstrings · array

    2. Filter with a stackstack (push / pop)

    3. Make phrasesarray · sliding window

    4. Visit each sourcesingly linked list

    The sources are nodes in a linked list. The program starts at the head, compares your phrases with that node's text, then follows the pointer to the next node until it reaches NULL.

    The C++ program finds each phrase with naive string matching. This page uses a hash set for the same lookup, which gives identical results faster.

    5. ScoreJaccard index
    6. Rankmerge sort

    The scores are sorted with merge sort: the list is split in half until each part holds one source, then the parts are merged back together, highest score first.

    How it works

    The detector doesn't try to understand meaning. It looks for the same short runs of words in both texts, because that is what copying and light editing leave behind. Here is what happens to one sentence:

    1. Clean

      Everything is lowercased and punctuation becomes a space, so “Learning,” and “learning” are the same word.

      machine learning is a branch of artificial intelligence
    2. Split

      The text is cut into a list of words.

      [machine, learning, is, a, branch, of, artificial, intelligence]
    3. Filter

      Words that appear in almost every text (“is”, “a”, “of”) and words shorter than three letters are dropped.

      [machine, learning, branch, artificial, intelligence]
    4. Make phrases

      A three-word window slides along the list.

      machine learning branch · learning branch artificial · branch artificial intelligence
    5. Compare and score

      The same is done to each source, and the phrases both texts share are counted. The score is the Jaccard index:

      similarity = shared ÷ (source phrases + your phrases − shared)

    Reading the score

    ScoreVerdictWhat it usually means
    25% and upHighLarge parts were copied, with or without small edits.
    10% – 25%ModerateSome passages were copied. Read the highlighted parts.
    under 10%LowA few shared phrases, normal for texts on the same topic.
    0%NoneNo shared phrases at all.

    Why three words?

    Single words match far too easily: any two essays about machine learning share the word “learning”. Long phrases miss text where one word was changed. Three words sits in between. You can try other lengths with the phrase length option.

    Limitations

    • It only sees wording. A paragraph rewritten fully in someone's own words scores close to zero, even if the ideas were taken.
    • Changing one word breaks every phrase that contains it, so heavy word-swapping lowers the score.
    • It only compares against the sources you give it. It does not search the internet.
    • It is made for English prose. Code, tables and other languages are not handled well.

    The C++ version

    The detector started as a C++17 command-line program, written without external libraries. This page is a port of it: same word list, same phrase length, same thresholds. On the sample files in the repository both report 25.86% for the copied essay.

    Each part of the program is built on a basic data structure:

    Singly linked list
    Holds the reference documents, so they can be added and removed while the program runs.
    Stack
    A generic, array-based stack filters common words out of the text.
    Arrays and strings
    Store the cleaned words and the three-word phrases.
    Naive string matching
    Finds each phrase in the source text, character by character.
    Merge sort
    Ranks the sources by score, highest first.
    Linear search
    Finds a document by its ID, and checks words against the stop-word list.

    The source code and build steps are on GitHub. There is also a single-file version, practical/plagiarism_demo.cpp, that walks through three test cases step by step in the terminal, and a project report with the full design.
