Semantic Plagiarism Detector

A document similarity engine that compares a suspect text against a corpus of reference documents. Text is normalised, filtered for stop-words, broken into word trigrams, and scored with the Jaccard similarity coefficient. Every stage is built on a core data structure implemented from scratch in C++17, with no external libraries.

1. Overview

Problem Statement and Objectives

Manually checking submissions against reference material is slow and inconsistent. This project automates the comparison and produces a quantitative, explainable similarity score for each reference document, together with the exact phrases that matched.

Objectives

  • Detect copied or lightly reworded content between a suspect document and a reference corpus.
  • Produce a numeric similarity score and a clear verdict for each reference document.
  • Rank reference documents from most to least similar.
  • Apply each FDS unit to a concrete role in the system.

Scope

  • Input: plain-text (.txt) reference documents and one suspect document.
  • Output: per-document similarity, verdict, matched phrases and ranked report.
  • Detection is lexical. It works on word sequences, not on meaning. Heavy paraphrasing or translation is out of scope.
  • Runs on Windows and Linux with any C++17 compiler.
2. Methodology

Processing Pipeline

Each reference document and the suspect document pass through the same six stages.

Normalisation

Convert to lowercase and replace punctuation with spaces.

Tokenisation

Split the cleaned text on whitespace into an array of words.

Stop-word filtering

Remove common function words and tokens of two characters or fewer, using a stack.

Trigram generation

Slide a window of three words over the filtered tokens.

Matching

Look up each suspect trigram in the reference using naive string matching.

Scoring and ranking

Compute the Jaccard similarity, classify it and merge sort the results.

Similarity measure
J(A, B) = |A ∩ B| / |A ∪ B| = |A ∩ B| / (|A| + |B| − |A ∩ B|)

A and B are the trigram sets of the reference and suspect documents. The score ranges from 0 (no shared trigrams) to 1 (identical trigram sets).

Verdict thresholds

Jaccard scoreVerdictInterpretation
≥ 25%HIGH PLAGIARISMSubstantial shared phrasing. The documents are very likely related.
10% – 25%MODERATE PLAGIARISMNoticeable overlap. Manual review is recommended.
0% – 10%LOW SIMILARITYA few shared phrases, which is common for documents on the same topic.
0%ORIGINALNo shared trigrams.

Stop-word filtering leaves only content words, so Jaccard scores are lower than raw word overlap. The thresholds are set for this.

5. Analysis

Time and Space Complexity

n = number of tokens in a document, g = number of trigrams (≈ n), L = length of the concatenated reference trigram string, m = length of one trigram, D = number of reference documents.

OperationData structureTimeSpace
Normalisation and tokenisationString, arrayO(n)O(n)
Stop-word filteringStackO(n)O(n)
Trigram generationArray (sliding window)O(n)O(g)
Trigram matching (one document pair)Naive string matchingO(g · L · m)O(L)
Jaccard computation—O(1)O(1)
Add reference documentSingly linked listO(D)O(n)
Rank resultsMerge sortO(D log D)O(D)
Find result by IDLinear searchO(D)O(1)

Naive matching is the dominant cost. It is used deliberately to demonstrate Unit 2. A hash set (average O(g)) or the KMP algorithm would remove this bottleneck.

6. Implementation

Project Structure and Usage

Repository layout

semantic-plagiarism-detector/ ├── src/ │ ├── main.cpp CLI menu │ ├── plagiarism_detector.h/.cpp │ ├── document_store.h/.cpp linked list │ ├── string_matcher.h/.cpp strings, n-grams │ ├── sorter.h/.cpp merge sort │ └── stack.h Stack<T> ├── samples/ test documents ├── docs/report.md project report ├── website/index.html this page └── Makefile

Build and run

make
./plagiarism_detector

Or compile directly:

g++ -std=c++17 -O2 -Wall -o plagiarism_detector src/*.cpp

Future scope

  • Hash-based or KMP matching to reduce lookup cost.
  • Synonym handling or word embeddings to detect paraphrasing.
  • Support for PDF and DOCX input.
