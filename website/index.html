How It Works

A five-step pipeline transforms raw text into a similarity verdict

📝
Step 01
Input & Tokenize
Raw text is split into word tokens stored in a dynamic Array.
→
🔤
Step 02
N-gram Extraction
Trigrams (3-word sequences) are extracted as strings and pushed onto a Stack for processing.
→
🔃
Step 03
Sort & Index
N-grams are sorted alphabetically; binary-search-ready for fast lookup.
→
🔍
Step 04
Naive Matching
Brute-force substring matching finds exact phrase occurrences in the suspect text.
→
📊
Step 05
Score & Verdict
Matched n-grams / total n-grams × 100 gives the similarity %, stored in a Linked List result chain.

Data Structures Used

Every FDS concept has a concrete role in the plagiarism pipeline

📊
Unit 1
Arrays
Stores tokenized words from both reference and suspect texts. Used as the primary data container for all subsequent processing steps.
O(n) traversal
🔤
Unit 2
Strings & Naive Matching
Brute-force pattern search scans every position in suspect text. Finds exact substring matches character by character.
O(n · m)
🔃
Unit 3
Sorting
N-grams are sorted lexicographically to enable efficient deduplication and faster set-intersection for similarity scoring.
O(n log n)
📚
Unit 4
Stack
A LIFO stack accumulates trigrams during the sliding-window extraction phase, enabling incremental n-gram building.
O(1) push/pop
🔗
Unit 5
Linked List
Matched phrase results are stored as nodes in a singly linked list, allowing dynamic result accumulation without pre-allocating space.
O(1) insert

Algorithm Complexity

Time and space analysis for each module in the pipeline

Module Data Structure Time Complexity Space Complexity Notes
Tokenization Array O(n) O(n) Split on whitespace; n = character count
N-gram Extraction Stack + Array O(n) O(n) Sliding window of size k=3
Sorting N-grams Array O(n log n) O(1) In-place JS Array.sort (TimSort)
Naive String Matching String O(n · m) O(1) n = text length, m = pattern length
N-gram Intersection Sorted Array O(n + m) O(k) Two-pointer merge on sorted sets
Result Accumulation Linked List O(1) O(k) k = number of matches found
Similarity Score — O(1) O(1) matched / total × 100
